Before you start

  • Open the ops console in a browser (local default: http://localhost:5180).
  • Only ADMIN and READONLY accounts use this web console. KIA / Zanzibar officers use the phone app.
  • Every staff account needs a valid Tanzania phone number for SMS password delivery (same notification platform as Soleil Nexus).
  • Access tokens last about 15 minutes; refresh tokens about 8 hours. If refresh fails, you are signed out automatically.
  • The Users menu is visible only to ADMIN. There is no 2FA on this console.
Getting started

1. Sign in

AuthADMIN / READONLYSMS reset

The sign-in screen is the first step into the ops console. Use your staff email and password, then choose Enter console.

  • Forgot password sends a short SMS code to the phone on your account (not an email link).
  • Enter the SMS code and a new password that meets staff security rules, then sign in again.
  • If an account requires a password change, you must complete that before the menus unlock.
  • Officer accounts (KIA / ZNZ) are blocked here and directed to the phone app.
Password rules match Nexus staff policy: at least 10 characters, with uppercase, lowercase, a number, and a special character from !@#$%^&*. The password must not include your name/email local-part, and must not be a common password.

2. Dashboard

Live snapshotAlerts

Dashboard is the home view after login. It summarizes custody across the Kilimanjaro → Zanzibar corridor.

  • Metric cards for received bags, airline readiness, airline custody, Zanzibar storage, ready-for-collection, and open exceptions.
  • Corridor strip showing origin and destination context.
  • Alerts list for seal issues, overdue collections, and other ops warnings.
Use Dashboard at the start of a shift to see whether the corridor is green or needs immediate attention.

3. Workload

SLAStaff load

Workload & SLA shows operational pressure: open exceptions, overdue SLA items, support volume, pending payments, and bags at each end of the corridor.

  • Refresh reloads the latest queue.
  • SLA queue lists bags that need attention, with priority, age, due time, and assignee.
  • Staff load shows how open exceptions are distributed across officers.

4. Exceptions

IncidentsResolve

Exceptions lists bag incidents such as seal mismatch, damage, delay, or uncollected bags.

  • Columns cover bag code, type, priority, status, and SLA timing.
  • ADMIN can open Resolve, add notes, and close an open exception.
  • Overdue rows are highlighted so critical issues stand out.

5. Support

TicketsAssign / Resolve

Support is the customer ticket triage inbox for questions about bag status, collection, or service issues.

  • Filter by status (All / OPEN / RESOLVED / CLOSED) and refresh the inbox.
  • ADMIN can Assign a ticket to a staff member and Resolve with notes.
  • Each row shows subject, customer, linked bag, status, assignee, and created time.

6. Bags

SearchCustody lookup

Bags is the search console for individual luggage in the corridor.

  • Search by bag code, customer name, phone, or passport, then press Search.
  • Click a row to open bag detail: status, location, seal, storage slot, and share message.
  • Use this when a passenger or airline desk asks “where is this bag right now?”

11. Catalog

ServicesPricing

Catalog is the service and pricing board for sellable products (for example door-to-desk custody).

  • Review service code, name, price, unit, sort order, and active status.
  • ADMIN can create services, set price (amount in minor units + currency + unit), and enable/disable offerings.
Amounts are stored in minor units (for example TZS 50,000.00 is entered as 5000000).

14. Users

ADMIN onlyStaff accountsPhone + SMS

Users manages staff accounts for the ops console and related roles. Phone numbers are required so passwords can be delivered and reset by SMS.

  • List existing users with name, email, phone, role, location, and active status.
  • Enable or disable accounts from the table.
  • Use Add user to create ADMIN, READONLY, KIA_OFFICER, or ZNZ_OFFICER accounts.
  • Provide a Tanzania phone number (for example +2557…). A welcome SMS with login details is queued to that number.
  • Passwords must meet Nexus staff rules. Use Generate in the dialog to create a compliant temporary password.
  • New users must change password on first sign-in. Admin password resets also SMS the temporary password to the user’s phone.
SMS is sent through the same chambaka notification service Nexus uses. If a phone number is missing or SMS is not configured in the environment, create/reset still succeeds but the SMS may not be delivered.

Reference

Sign out & session notes

Use the door/arrow icon at the bottom of the side rail to sign out. Your local session is cleared immediately.

If the access token expires, the console tries the refresh token. If refresh fails, you are logged out and returned to sign-in with the message “Your session expired. Sign in again.”

Role quick guide

  • ADMIN — full console, including Users, refunds, and most write actions.
  • READONLY — can view ops data; write actions are blocked.
  • KIA_OFFICER / ZNZ_OFFICER — phone app roles, not this web console.

Password & SMS

  • Self-serve reset uses a 5-character SMS code (valid about 10 minutes).
  • Staff passwords follow Nexus complexity rules; this console does not use 2FA.
  • Welcome / admin-reset SMS messages include temporary credentials and ask the user to change the password after signing in.

Need help?

For environment setup, run the UI with npm run dev and point API traffic to the GoLyt backend on port 8070.

SMS delivery needs the shared notification service (app.notification.* / APP_NOTIFICATION_*) configured the same way as Nexus.
